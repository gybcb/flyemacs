#+TITLE: Emacs 31 配置说明
#+STARTUP: showall

* 这套配置是什么

只干一件事：**改配置文件**。JSON / JSONC / YAML / TOML / INI / .env /
nginx.conf / tmux.conf / ssh_config / gitconfig / gitignore / gitattributes /
各种 .zshrc、.bashrc、.envrc。

两条硬指标：

1. 打开就校验：进 buffer 时 eglot 懒拉起 language server，语法错误当场标出来。
   只做语法层校验，不查 JSON Schema、不查语义规则。
2. 启动尽量快：实测 ~0.16s~（暖缓存，~after-init-time - before-init-time~），
   预算 ~0.6s~。启动期不起子进程、不递归扫 ~.el~、不联网刷包索引。

为此删掉了原来的 IDE 化部分：lsp-bridge、company、yasnippet、neotree、jupyter、
python 模块、color-rg、aweshell、三个 git submodule —— 细节见文末「已移除」。

架构图见 [[file:ARCH.org][ARCH.org]]。

* 支持的格式与校验

| 格式                | major mode                            | 语法校验              | 依赖的外部程序                   |
|---------------------+---------------------------------------+-----------------------+----------------------------------|
| json / jsonc        | ~json-ts-mode~（退路 ~js-json-mode~）   | ✅ ~Property expected~ | ~vscode-json-language-server~    |
| yaml                | ~yaml-ts-mode~                        | ✅                    | ~yaml-language-server~           |
| toml                | ~toml-ts-mode~（退路 ~conf-toml-mode~） | ✅                    | ~taplo~ 优先，否则 ~tombi~       |
| .zshrc / .bashrc / .envrc / *.sh | ~sh-mode~                             | ✅ shellcheck 诊断     | ~bash-language-server~ + ~shellcheck~ |
| ini / cfg / setup.cfg | ~conf-windows-mode~                  | ❌ 只高亮             | 无                               |
| .env / nginx.conf / tmux.conf / ssh_config / .gitignore / .gitattributes | ~conf-unix-mode~ | ❌ 只高亮 | 无 |
| gitconfig           | ~conf-windows-mode~                   | ❌ 只高亮             | 无                               |

后三类没有可靠的 LSP（要么不存在，要么装上就会对 vim 脚本之类的东西乱报），
所以按设计只给高亮、不拉进程 —— 打开这些文件不会产生任何子进程。

#+begin_note
JSON 一项需要 ~flywind-config-lsp-settings~：eglot 连上后会 push 一个 settings，
~vscode-json-language-server~ 把「收到 settings 但 ~json.validate.enable~ 未设」当成
校验关闭。实测：settings 为空 → 再坏的 JSON 也 0 条诊断；~enable=t~ → 立刻报
「Property expected」。所以 ~'(:json (:validate (:enable t)))~ 是必需的，别删。
#+end_note

配置本身不含外部程序，缺了会怎样都写在 ~M-x flywind-check-config~ 里。

语法库装进 ~tree-sitter/~，需要 cc + ~tree-sitter~ CLI。

交互式提问（还会顺带联网），本配置关掉它（~treesit-auto-install-grammar~），

* 主题：自动跟随浅色 / 深色

终端里真正相关的是终端自己的配色板，不是 macOS 的设置：终端是浅色调色板时载深色主题
很难看。所以判据按环境分开、各自独立：同一台机器可以一边开浅色 Ghostty、一边开深色
iTerm，缓存按环境分格存，互不顶掉。

| 环境              | 依据                                   | 结果                        |
|-------------------+----------------------------------------+-----------------------------|
| GUI               | macOS AppleInterfaceStyle              | 深色 -> doom-solarized-dark  |
| Ghostty（两档主题） | macOS 外观                        | Dark -> dark            |
| 其它终端（iTerm） | COLORFGBG 背景色号（iTerm 默认 12;8）  | 8 -> dark                   |
| 认不出来          | 无信号                                 | 兜底 dark                   |

Ghostty 是个坑，而且坑了两层：

1. 它**不导出 COLORFGBG**（shell-integration-features 里没有这一项），只看那个变量会在
   Ghostty 里永远判成深色。
2. 改读 =ghostty +show-config= 也不行：它会把 =theme = light:X,dark:Y= 解成具体颜色，
   但**不跟随系统外观** —— 实测系统浅色和深色两种情况下它都输出 light 那档的
   #eff1f5（它只是个普通 CLI 进程，没那个上下文）。

所以分两种配置处理（=flywind-theme--parse-ghostty=）：theme 同时给了 light: 和 dark:
两档（官方文档：两档都给才会自动切）时，终端自己跟 macOS，**看 macOS 外观**；只给
一档或手写死 background 时配置是静的，+show-config 解析出的背景色就是终端真正的背景，
拿它算亮度（阈值 =flywind-theme-light-luminance=，默认 128）。一次探测靠一条 shell 同时
拿配置段和 AppleInterfaceStyle，用标记分隔，不串两个子进程。

不是白捡的：Emacs 31 有个会随系统主题变化自动更新的变量 toolkit-theme，但它自己的文档
明写只在 PGTK / Android / MS-Windows 构建里赋值 —— macOS 的 ns 构建不在其列，ns-win.el
里也找不到任何读 NSAppearance 的代码。所以 Mac 上只能自己查 defaults（约 10ms）。

要点：

- 启动期稳态零子进程。先读本格缓存（.local/cache/theme-appearance，纯文件读）立刻载
  主题，不查系统、也不会「先深后浅」闪一下。本格第一次（无缓存）同步查一次：
  defaults 约 10ms、Ghostty 那条约 20ms，实测冷启动 0.188s vs 常态 0.171s。不想花
  这一次就设 =flywind-theme-probe-at-startup= 为 nil。
- 启动后马上再异步核对一次（=flywind-theme--start-watching= 里踢一脚）：缓存可能是
  上一个外观下留下的，等满一个轮询周期才纠正的话，中间这段主题就是错的。异步
  = 不占启动时间。之后才是焦点回来 / 每 flywind-theme-check-interval 秒。
- 终端也载真主题、也跟着实时变（以前 emacs -nw 是裸 face，且只看启动快照）：载主题
  代价约 10ms，0.16s -> 0.17s。COLORFGBG 已经是准数的终端不装探测器，不白忙。
- ns-appearance 故意不设：不设时 macOS 自己管窗口边框和标题栏、跟着系统走；显式设成
  dark / light 反而把边框钉死，从此和系统脱钩。
- 一个 Emacs 进程只能有一个主题方向（主题是全局的）。GUI 与终端混用同一进程时，
  用 M-x flywind-theme-toggle 现场切。

命令与变量：

- M-x flywind-theme-toggle — 手动在浅 / 深之间切并钉住，同时写进本格缓存（下次启动沿用）
- M-x flywind-theme-follow-system — 取消钉住 + 抹掉本格缓存，重新跟随
- M-x flywind-theme-report — 打印当前主题按什么定的：环境、各信号源、探测器命令、分格缓存
  全表都列（GUI 分支在 Emacs.app 里跑一次即可确认）
- flywind-theme-light / flywind-theme-dark — 换主题对（doom-themes 里 13 个 light 变体可选）
- flywind-theme-force — 钉住：nil 跟随 / light / dark（只管当前进程；跳重启靠缓存）
- flywind-theme-check-interval — 轮询秒数，0 = 不轮询，只在启动和焦点回来时查
- flywind-theme-probe-at-startup — 无缓存时允许启动同步探一次（默认 t）
- flywind-theme-light-luminance — 终端背景亮度阈值，>= 它算浅色

* mode line：为什么不用 doom-modeline

你原来那条是 ~doom-modeline~。它其实一直没生效：~use-package~ 写在
~(when (display-graphic-p) ...)~ 里，终端跑的时候整块被跳过 —— 你看到的从来是
 Emacs 默认那条。要「快一点又好看」，就自己拼了一条 ~flywind-modeline~，
~doom-modeline~ 留在清单里当可选档（~flywind-modeline-implementation~ 设成 ~doom~
就切回去，当场生效）。

本机（Apple Silicon + Ghostty tty）交替测三轮：

| 实现               | 启动   | 单次渲染 | 相对默认 |
|--------------------+--------+----------+----------|
| ~flywind-modeline~ | 0.279s |   140 us | 0.7x     |
| Emacs 默认         | 0.296s |   208 us | 1.0x     |
| ~doom-modeline~    | 0.347s |   560 us | 2.7x     |

自己这条比默认还便宜一点：~mode-line-format~ 里只三个 ~:eval~（身份、分支、编码），
其余走 C 侧的 ~%l~ / ~%c~ / ~%P~ 转义与内置的 ~mode-line-modes~。~doom-modeline~
每次重绘都要跑一批 ~:eval~（包括 ~project-current~ 那类目录探索），那是它慢的主因。

长相（~│~ 是分隔符，图标用 Nerd Font 码位）：

#+begin_example
   init.el │ ⑂ master │ UTF-8 LF  1:0 All  (Elisp/l)
  .gitignore │ ⑂ master │ UTF-8 LF  1:0 All  (Conf[Unix])
#+end_example

四条约束，改之前先看 ~flywind-modeline.el~ 顶部注释：

- 颜色一律 ~:inherit~ 主题已经管好的 face。主题会在浅 / 深之间自动翻（见上一节），
  写死的颜色在那边一定翻车。
- 图标码位不是猜的：名字取自 nerd-icons 的数据表，再用 ~fc-query~ 对
  ~JetBrainsMonoNerdFont-Regular.ttf~ 的 cmap 逐个验过存在。Ghostty 的
  ~font-family~ 也是同一个 Nerd Font，所以 tty 与 GUI 同一套字形。终端不是
  Nerd Font 就把 ~flywind-modeline-icons~ 设 nil 退回 ASCII，否则是豆腐。
- 渲染路径上零 I/O：分支从 ~vc-mode~ 那根串里剔，不起 git；只读状态取
  ~buffer-read-only~，不用 ~file-writable-p~ 去 stat。
- 编码段读 ~buffer-file-coding-system~，显示成 ~UTF-8 LF~。~%z~ 不行 —— 它给的是
  终端自己的编码（实测 tty 里渲染成 ~UUU~），而配置文件真正要盯的是 LF / CRLF。

顺带收掉四个纯噪音 lighter：~WK~（which-key）、~ h~（hungry-delete）、~ElDoc~、
~ARev~（flywind-dired 里 ~global-auto-revert-mode~ 顺带挂的）。它们每个 buffer 都
占一格又不带信息，清单见 ~flywind-modeline-hidden-minor-modes~。抹的动作是本模块
自己改 ~minor-mode-alist~（写成 ~("")~），没依赖 ~diminish~ 包：走它的 autoload 会让
byte-comp 报 ~the function 'diminish' is not known to be defined~，运行时还要白付一次
启动磁盘读。动作在 ~flywind-basic.el~ 的 ~flywind-hide-minor-mode-lighter~（public），
因为 ~flywind-ui.el~ 也要用：volatile-highlights / whitespace / rainbow-mode 的
lighter 是实打实的 ~ VHl~ / ~ ws~ / ~ Rbow~（实测），不抹就在 mode line 上常驻 ——
它们原先靠 ~:diminish~ 关键字，现在改成在各自 :config 里调这个函数，~diminish~
包已从清单删掉。

* 常用命令

- ~M-x flywind-check-config~ — 体检，结果写进 ~*flywind-check-config*~：字节编译
  有无 Error/Warning、ELPA 缺哪些包、三个语法库是否就位、四个 language server
  是否可执行。带 ~C-u~ 前缀全量重编，把每个文件的警告重现一遍。
- ~M-x flywind-modeline-report~ — 当前 mode line 用哪条实现、图标开没开、单次
  渲染多少微秒，外加一行样例与可调变量。
- ~M-x flywind-tests-run~ — 主题跟随的回归用例（102 项断言），明细在
  ~*flywind-tests*~。缓存绑到临时文件，不碰 ~.local/cache~ 里真那份，跑完把主题
  还原成跑之前的方向。命令行跑法见下。
- ~M-x flywind-install-treesit-grammars~ — 装 json/yaml/toml 语法库
- ~M-x flywind-install-missing-packages~ — 刷索引并装 ~flywind-packages~ 里缺的包
- ~M-x flywind-sync-package-selected-packages~ — 把 ~flywind-packages~ 同步进
  ~package-selected-packages~（存 ~.local/etc/custom.el~）。同步过之后
  ~package-autoremove~ / package-menu 才会把清单外的包正确当依赖判断。
- ~M-x flywind-byte-compile-config~ — 只编自有 ~.el~（early-init / init / user-lisp），
  不扫第三方目录。~flywind-check-config~ 已经含这一步。
- ~M-x flywind-config-refresh-mode-mappings~ — 语法库装好后重建 major mode 映射，
  不必重启。
- ~M-x flywind/consult-search-dwim~（~C-s~）— 文件里 ~consult-line~，其它 buffer 里
  ~consult-ripgrep~

改完主题逻辑（~flywind-ui.el~ 里 ~flywind-theme-*~ 那一段）跑一遍回归最省事——
那套坑全是「静默返回 nil」或「静默判成另一个方向」，不会报错：

#+begin_src shell
cd ~/.emacs.d
emacs --batch -l early-init.el -l init.el -l user-lisp/flywind-tests.el \
      --eval "(flywind-tests-run-batch)"
#+end_src

全过退出码 0；有失败退出码 1，并打印期望 / 实得。

启动期不联网：不 ~package-refresh-contents~、不用 ~:ensure~。

* 启动预算与测量

预算：暖缓存 ~after-init-time - before-init-time < 0.6s~。本机实测 ~0.160s~（跑四次，
首趟 ~0.204s~）。~emacs -nw~ 要有 tty，非交互 shell 里用 ~script~ 造一个：

#+begin_example
cat > /tmp/st.el <<'EOF'
(add-hook 'emacs-startup-hook
          (lambda ()
            (append-to-file (format "STARTUP %.3f\n"
                            (float-time (time-subtract after-init-time before-init-time)))
                            nil "/tmp/startup.txt")
            (kill-emacs)))
EOF
rm -f /tmp/startup.txt
for i in 1 2 3; do script -q /dev/null emacs -nw -l /tmp/st.el >/dev/null 2>&1; done
cat /tmp/startup.txt
#+end_example

~--eval~ /~-l~ 里的 ~after-init-time~ 还是 ~nil~（它在命令行参数处理完之后才赋值），
所以要挂 ~emacs-startup-hook~。

启动期不起子进程：~exec-path~ 用 ~flywind-extra-exec-path~ 静态注入
（/opt/homebrew/bin、/opt/homebrew/sbin、/usr/local/bin、~/.local/bin，不存在就跳过），
取代 ~exec-path-from-shell~ 的 ~bash -l~ 子进程。从 Dock 启动的 Emacs 拿不到
shell 的 PATH，这里也是它的补救点 —— 换了别的环境就改这个变量。

** 窗口

用原生 ~display-buffer-alist~ 取代 popwin，并抵消 Emacs 31 的新默认值
（~split-window-preferred-direction~ = ~'vertical~、~split-width-threshold~ = 160、
~transpose-dedicated-windows~ = ~nil~）。窗口操作走内置 ~windmove~：

| 键               | 作用                                 |
|------------------+--------------------------------------|
| ~S-<方向>~       | 选那个方向的窗口                     |
| ~C-x o~ / ~C-x O~ | 循环下一个 / 上一个窗口              |
| ~C-x S-<方向>~   | 与那个窗口交换 buffer                |
| ~C-x M-<方向>~   | 关掉那个方向的窗口                   |
| ~C-x 4 <方向>~   | 在那个窗口显示下一个命令的 buffer    |
| ~C-x C-z~        | zoom-window：当前窗口全屏 / 还原     |

失去的能力：按编号跳到第 N 个窗口（31 无内置等价物，需要时重新加 ace-window）。

* 已知取舍

- 抹 mode line 上的 lighter 要写成 ~("")~，不是裸空串 ~""~：mode line 的 lighter 位认
  「列表形式的 lighter」，裸空串在 tty 的渲染路径里判成无效 —— 实测把 cdr 设成 ~""~
  之后，每个被抹的 mode 都在 mode line 上打出一个 ~*invalid*~（当时四个）。batch 里
  渲染不出这个差别（实测同样返回空串），所以回归只能查结构：条目必须是列表、
  不能是裸字符串。
- ~global-minor-mode-alist~ 在 Emacs 31 里**不存在**（实测 void-variable）。它只活到
  Emacs 24 那一代，全局 minor mode（which-key / auto-revert 这类）的 lighter 现在就
  挂在 ~minor-mode-alist~ 上，抹 lighter 只改一个表就够。
- ini / ~.env~ / nginx / tmux / ssh_config / gitconfig 只高亮不校验：没有可靠的
  LSP，宁可没有诊断也不要错得离谱的诊断。
- TOML 有两个候选：~taplo~ 与 ~tombi~（Emacs 31 eglot 默认项）。装了 taplo 就用
  taplo；本机现在用的是 tombi。改了 ~flywind-config-lsp-programs~ 要重启 Emacs
  ——~eglot-server-programs~ 只在 eglot 加载时算一次。
- 自有 ~.el~ 冷编译（先删 ~.elc~）必须零告警，不是「能过就行」。三类告警各有固定
  解法，实测都落在本配置里：
  * 在 =with-eval-after-load= 里写别的包的变量（=eglot-server-programs=
    =treesit-language-source-alist=）→ 报 free variable，补
    =(eval-when-compile (require 'eglot) (require 'treesit))=（只编译期加载，
    运行时不靠它）。
    注意别看到告警就当变量名写错：=treesit-auto-install-grammar= 是 Emacs 31 的
    真变量（实测 boundp，默认 =ask=，就是那个联网提问）。
  * 文件头 =eval-when-compile (require 'dired)= 会让编译器「只在编译期认识」某些函数，
    于是报 might not be defined at runtime —— 运行时保证已经在 =with-eval-after-load=
    里了，这种假报用 =with-no-warnings= 压掉并写清理由。
  * 废弃变量先看 docstring 再决定改名还是删。=org-edit-src-content-indentation= 在
    Org 9.10.3 里明写 preserve-indentation 非 nil 时无效，而本机正是 t，所以直接删
    （接替名也在，但本模块跑在 org-src 加载前，改名等于先于它的 defcustom 赋值）。
  还有个只有冷编译才暴露的运行期坑：modeline 的 =after-load-functions= 回调裸用
  =(when flywind-modeline-mode ...)=，而那个 symbol 要到同文件后面的
  =define-minor-mode= 才存在 —— 启动期自动编译会触发这个 hook，实测连带 8 个文件
  报 void-variable 编译失败。改成 =bound-and-true-p=。
- 字节编译放在 ~flywind-check-config~ / ~flywind-byte-compile-config~ 里，不在启动期
  递归扫第三方目录；但自有 ~.el~ 仍在启动期按时间戳编（~.elc~ 过期会静默盖住
  源码改动，这个险不值得冒）。
- Org 与终端相关模块保留：它们不在删除清单里，且 ~with-eval-after-load~ 让
  启动成本为零。
